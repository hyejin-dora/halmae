# HALMAE · 할매

AI 기반 사주·점성술 자기성찰 서비스 MVP

생년월일과 출생 정보로 사주 네 기둥과 태양궁·달궁·상승궁, 대운·세운을 계산하고,
그 값을 근거로 "할매" 캐릭터가 3단계에 걸쳐 조언을 건넵니다.

```
Step 1  →  Step 2  →  Step 3  →  올해의 흐름 (대운 × 세운)  →  올해의 카드
```

계산은 전부 파이썬이 합니다. Gemini 는 **계산이 끝난 값을 해석만** 합니다.
대운·세운도 예외가 아닙니다 — Gemini 에게 간지나 연도를 뽑게 하지 않습니다.

> 엔터테인먼트와 자기성찰을 위한 서비스입니다.
> 건강·투자·법률 판단을 대신하지 않습니다.

## Tech Stack

- **Python** 3.11+
- **Streamlit** — 화면
- **Gemini API** (`google-genai`) — 할매의 3단계 답변 · 올해의 흐름 · 올해의 카드
- **Supabase** (PostgreSQL) — 행동 로그 · 피드백 · 올해의 카드 저장
- **Korean Lunar Calendar** — 음력/양력 변환과 간지 계산
- **Swiss Ephemeris** (`pyswisseph`) — 태양·달 위치와 Ascendant

## 필요한 환경변수 / Secrets

이름만 적습니다. **실제 값은 이 파일이나 코드에 절대 적지 마세요.**

| 이름 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | ✅ | Gemini API 열쇠. Mock 모드에서는 없어도 앱이 뜹니다 |
| `SUPABASE_URL` | ✅ | Supabase 프로젝트 주소 |
| `SUPABASE_SECRET_KEY` | ✅ | Supabase 서버용 비밀 열쇠(service_role) |
| `HALMAE_DEV_KEY` | 권장 | 개발자 지표 화면 `?dev=...` 의 암호. 없으면 `?dev=1` 로 누구나 열림 |
| `HALMAE_USE_MOCK_AI` | 선택 | `"false"` 면 실제 Gemini 호출 |
| `HALMAE_DEV_MODE` | 선택 | `"false"` 면 품질용 모델 사용 |
| `HALMAE_STORAGE` | 선택 | `auto`(기본) / `supabase` / `local` |

`SUPABASE_PUBLISHABLE_KEY`(anon key)는 이 앱에서 **쓰지 않습니다.**
저장은 모두 서버 쪽에서 일어나기 때문입니다.

읽는 순서는 `config.get_secret()` 한 곳에 있습니다.

```
1순위  os.environ    내 컴퓨터 · Codespaces
2순위  st.secrets    Streamlit Community Cloud
```

덕분에 개발용 코드와 배포용 코드를 따로 만들 필요가 없습니다.

## Deploy · Streamlit Community Cloud

1. GitHub 저장소에 push
2. [share.streamlit.io](https://share.streamlit.io) → **New app** → 저장소 선택
3. **Main file path** 를 `app.py` 로 지정
4. **Advanced settings → Secrets** 에 위 표의 값을 TOML 형식으로 입력

```toml
GEMINI_API_KEY = "..."
SUPABASE_URL = "https://xxxxxxxx.supabase.co"
SUPABASE_SECRET_KEY = "..."
HALMAE_DEV_KEY = "..."
```

5. **Deploy**

배포 직후에는 Mock AI 모드로 뜹니다 (Gemini 무료 quota를 쓰지 않습니다).
실제 Gemini로 바꿀 때는 Secrets 에 `HALMAE_USE_MOCK_AI = "false"` 한 줄을 추가하고
저장하면 됩니다. **코드를 고치거나 다시 push 할 필요가 없습니다.**

## 올해의 카드 정책

올해의 카드는 **"같은 사람 + 같은 출생정보 + 같은 연도"에 딱 한 장**입니다.
연애 · 취업/커리어 · 돈 · 인간관계 · 삶의 방향, 어떤 고민으로 접속해도 같은 카드입니다.

그래서 카드를 만들 때 아래는 **넣지 않습니다.**

고민 분야 · 추가 질문 · Step1/2/3 응답 · 고민 해석 텍스트 ·
Premium 관련 내용 · 1~3단계 대화 이력 · 이름

넣는 것은 계산이 끝난 값뿐입니다.

사주(년주 · 월주 · 일주 · 시주 · 일간 · 오행) ·
점성술(Sun · Moon · Ascendant) · 현재 연도와 그 해의 간지

`stable_key` 도 같은 규칙입니다 — 연도와 정규화된 출생정보만 들어갑니다.
행동 지침(actions)도 "이력서를 써라"처럼 특정 고민에 종속되지 않고,
여러 삶의 영역에 적용할 수 있는 원칙으로 씁니다.

### 카드 그림 (타로 카드형)

카드는 세로형 타로 카드로 그려집니다 — 상단 `YEAR CARD` · 중앙 그림 · 하단 `THE ___`.
그림을 정하는 두 칸은 `card_data`(jsonb) **안에** 들어갑니다.
`cards` 테이블에 새 칸을 만들지 않으므로 이미 저장된 카드는 건드리지 않습니다.

| 칸 | 값 | 누가 정하나 |
|---|---|---|
| `visual_theme` | `breakthrough` `expansion` `balance` `transformation` `grounding` `connection` `clarity` `renewal` 중 하나 | Gemini (사주 · 점성술 · 올해 간지만 보고) |
| `image_url` | 그려진 일러스트 주소 (없어도 됨) | 사람 — 모델에게 묻지 않습니다 |

- `image_url` 이 있으면 그 그림을, 없으면 `visual_theme` 에 맞는 선화 placeholder 를 그립니다.
- 두 칸 모두 카드와 함께 저장되므로 **다시 들어와도 같은 그림**입니다.
  (재접속 때 `visual_theme` 을 Gemini 에게 다시 묻지 않습니다)
- 이 칸들이 없는 **옛날 카드**는 지우지 않습니다. `balance` 로 읽어 그대로 보여줍니다.
- 그림 여덟 장과 다음 단계용 이미지 프롬프트는 `card_visuals.py` 한 곳에 있습니다.

```bash
python card_store.py                      # 저장된 카드 목록
python card_store.py --delete <열쇠앞자리>  # 그 카드 한 장만 지우기
python card_store.py --sql                # Supabase 에서 지우는 SQL 보기
```

개발자 모드(`HALMAE_USE_DEV_MODE=1`)에서는 카드 아래
**"이 카드만 다시 뽑기"** 버튼으로 지금 세션의 카드 한 장만 버릴 수 있습니다.
`cards` 테이블을 통째로 비우는 길은 어디에도 두지 않았습니다.

이름 · 생년월일 원문 · 출생시간 · 출생지역 원문 · 위도/경도 ·

서비스가 도는 동안 화면과 프롬프트에만 쓰이고, 행동 로그에는 들어가지 않습니다.

모델 이름, 단계 번호뿐입니다.
올해의 카드는 되돌릴 수 없는 SHA-256 열쇠와 카드 결과만 저장합니다.

## 연애·관계 — 관계 상태를 묻는 이유

고민 분야가 "연애" 하나뿐이던 시절, 할매(Gemini)는 사용자를 **솔로라고 짐작**하고
"소개팅에 나가라", "새로운 사람을 만나보라" 같은 조언을 했습니다.
기혼인 사람에게는 쓸모없다 못해 무례한 말이 됩니다.

그래서 관계 상태를 **추측 대상에서 사용자가 고르는 확정 입력값으로** 옮겼습니다.
사주 명식·대운·세운과 똑같은 원칙입니다 — 사람이 정하고, 할매는 해석만 합니다.

### 조건부 질문

고민 분야에서 **`연애·관계`** 를 고른 사람에게만 한 번 더 묻습니다.

```
현재 관계 상태를 알려주세요.
  ○ 솔로·새 인연     ○ 썸·연애중
  ○ 기혼·부부·가정   ○ 말하고 싶지 않아요
```

- 다른 고민(취업/커리어 · 돈 · 인간관계 · 삶의 방향 · 기타)에서는 **보이지 않습니다.**
- **미리 골라두지 않습니다**(`index=None`). 첫 항목이 선택돼 있으면 그냥 지나친
  사람이 솔로로 기록되기 때문입니다. 비운 채 제출하면 `말하고 싶지 않아요` 로 봅니다.
- 관계 상태를 골랐다가 다른 고민으로 바꿔 제출하면 그 값은 **담기지 않습니다.**

### 상태별 해석 정책

값은 `halmae_ai.RELATIONSHIP_POLICIES` 한 곳에 있고, 프롬프트가 그 글을 그대로 씁니다.

| 관계 상태 | 무엇을 중심으로 | 무엇을 하지 않는지 |
|---|---|---|
| 솔로·새 인연 | 새 관계를 만드는 방식 · 사람을 만나는 방식 · 관계 진입 패턴 | 사귀는 상대나 배우자가 있다고 전제하지 않음 |
| 썸·연애중 | 지금 상대와의 소통 · 관계 진전 · 되풀이되는 갈등과 선택 | "새로운 사람을 만나보라" 금지 |
| 기혼·부부·가정 | 배우자와의 관계 · 소통 · 가정 안의 균형과 행동 | **새로운 인연·소개팅·이별 권유 절대 금지** |
| 말하고 싶지 않아요 | 관계 전반의 성향과 되풀이되는 행동 패턴 | 어느 상태도 추측하지 않음 · '연인/배우자/솔로' 같은 낱말 대신 '상대·가까운 사람' |

### 지어내지 못하게 막는 방법

`RELATIONSHIP_LOCK_RULES` 가 사주 명식의 잠금 규칙과 같은 방식으로 붙습니다.

- 위 관계 상태는 사용자가 직접 고른 확정값이다. **다른 상태를 가정하지 마라.**
- 상태를 짐작하게 하는 표현("아직 인연을 못 만났으니")을 쓰지 마라.
- 추가 질문에 상황이 **분명하게** 적혀 있으면 참고하되, 분명하지 않으면 단정하지 마라.
- 사주·점성술 값으로 관계 상태를 역추적하려 하지 마라.
- 행동 지령(3단계)은 특히 조심하라 — 어긋나면 그대로 무례한 말이 된다.

이 블록은 **Step 1 · 2 · 3 과 올해의 흐름 프롬프트에 매번 다시 붙습니다.**
대화가 길어질수록 모델이 슬금슬금 다른 상태로 흘러가기 때문입니다.

### 올해의 카드에는 넣지 않습니다

관계 상태는 `stable_key` 에도 카드 프롬프트에도 들어가지 않습니다.
**같은 출생정보 + 같은 연도면, 관계 상태가 달라도 같은 카드**입니다. (정책 변경 없음)

### 저장하지 않습니다

관계 상태는 미리 정해진 선택지지만 **행동 로그에 저장하지 않습니다.**
`analytics.FIELDNAMES` 여섯 칸은 그대로입니다.

## 대운 · 세운 계산 기준

명리 학파마다 갈리는 자리라, 이 서비스는 **아래 규칙 하나만** 씁니다.
자세한 설명과 코드는 `daeun.py` 맨 위 주석에 있습니다.

| 무엇을 | 어떤 기준으로 |
|---|---|
| 순행 / 역행 | 양간년 남자 · 음간년 여자 → **순행** / 음간년 남자 · 양간년 여자 → **역행** |
| 절기 | 12절 (입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한) — 월주와 같은 표 |
| 대운 시작 시점 (대운수) | 순행은 **다음 절입까지**, 역행은 **직전 절입까지**의 시간 ÷ 3 (3일 = 1년) · 소수 첫째 자리 반올림 · 최소 1 |
| 대운 간지 진행 | **월주**에서 출발해 60갑자를 순행 +1 / 역행 −1 · 한 대운 10년 |
| 나이 · 연도 | 만 나이 · n번째 대운 시작 연도 = 사주 기준 출생연도 + 대운수 + 10 × (n−1) |
| 세운 | `date.today()` 로 지금 연도를 가져와 그 해의 간지 계산 (해가 바뀌는 기준은 **입춘**) |

### 알아둘 점

- **성별이 필요합니다.** 대운 방향(순행/역행)이 성별로 갈리기 때문입니다.
  그래서 입력 화면의 성별 칸 아래에 한 줄로 미리 알려둡니다.

  > 대운은 성별에 따라 흐름의 방향이 달라져, 성별을 선택한 경우에만 제공해요.

  `성별 = 응답하지 않음` 이면 **대운만 건너뛰고** 올해의 흐름은 세운으로
  그대로 보여줍니다. (오류가 아니라 '건너뜀'이라 경고 상자를 띄우지 않습니다)
  Step 1~3 · 세운 · 올해의 카드 · Supabase 는 모두 그대로 동작합니다.

- **화면에는 나이보다 연도를 먼저 씁니다.**

  ```
  지금 대운
  2017 ~ 2026        ← 큰 글씨
  경오(庚午)          ← 작은 글씨
  ```

  대운수는 절입까지의 거리를 3으로 나눠 **반올림**한 값이라, 경계에 걸리면
  만세력에 따라 한 살 차이가 납니다. 나이를 크게 써두면 그 숫자를 절대값처럼
  받아들이게 되므로, 만 나이는 아래 작은 글씨로만 두고
  "나이 셈은 만세력마다 한 해쯤 다를 수 있으니 연도를 기준으로 보라"고 함께 적습니다.
  할매(Gemini)에게도 같은 규칙을 겁니다 — 시기는 나이가 아니라 연도로 말합니다.

- 만세력이 세는 나이로 적는 경우 나이가 1살 달라 보입니다.
  이 서비스가 실제로 쓰는 값은 '연도'라 해석에는 영향이 없습니다.
- 세운은 코드에 연도를 적어두지 않습니다. (`test_daeun.py` 가 그것을 검사합니다)

## 올해의 흐름 (대운 × 세운)

Step 3 다음, 올해의 카드 앞에 놓이는 **다리(bridge) 구간**입니다.
Step 번호를 붙이지 않습니다 — 1/3 · 2/3 · 3/3 구조는 그대로입니다.

```
[할매, 올해 흐름도 봐줘]
      ↓
올해의 흐름 · 대운 × 세운
   A. 지금 네가 지나고 있는 대운      ← 성별을 안 골랐으면 이 칸만 생략
   B. 올해의 세운
   C. 대운과 세운이 만나는 자리 (밀 것 / 조심할 것 / 네 고민과의 연결)
      ↓
[2026 올해의 카드 보기]
```

성별을 고르지 않은 사람에게는 **A 칸만 통째로 빠집니다.**
제목도 `대운 × 세운` 대신 `올해의 세운` 이 되고, 아래 한 줄만 덧붙습니다.

> 성별을 고르지 않아 대운은 건너뛰었단다.

긴 설명은 입력 화면에서 이미 했으므로 결과 화면에서는 되풀이하지 않습니다.
할매에게도 "대운 이야기는 하지 말고, 성별을 알려달라고 조르지도 말라"고
프롬프트에서 못 박습니다.

- 간지와 연도 구간은 **파이썬 계산값**이 화면에 그대로 뜹니다.
  할매의 글에서 간지를 되읽어오지 않습니다.
- 분량은 900~1,400자입니다. Step 2·3 처럼 길게 쓰지 않습니다.
- 계산이나 해석이 실패해도 **이 구간에서만** 안내를 띄웁니다.
  Step 1~3 과 올해의 카드는 살아 있습니다.

## 로딩 화면과 처리시간

`streamlit run app.py 2>&1 | grep PERF` 로 어느 구간이 오래 걸리는지 볼 수 있습니다.

```
[PERF] saju_calculation: 0.01s
[PERF] astrology_calculation: 0.98s
[PERF] gemini_step2: 9.66s
```

- 처리시간은 **개발 로그에만** 남습니다. 사용자 화면에는 보이지 않습니다.
  (개발자 모드에서는 결과 화면 아래 '개발자용 · 처리시간 보기' 에서 요약을 봅니다)
- 로그에는 구간 이름과 초만 적습니다. 개인정보는 들어가지 않습니다.
- 사주·별자리·대운은 **같은 입력이면 다시 계산하지 않습니다.**
  세션 안에서는 입력 지문으로, 세션 밖에서는 `st.cache_data` 로 재사용합니다.
- 기다리는 동안에는 단계별 문구가 바뀝니다 (`progress.py`).
  Gemini 한 번 호출처럼 안이 안 보이는 구간도 글이 바뀌어,
  "앱이 멈췄나?" 라는 오해가 생기지 않게 했습니다.
